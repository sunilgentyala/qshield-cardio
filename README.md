> **Research software. The models have not established clinical safety or effectiveness.** They must not determine eligibility for routine blood-pressure checks, diagnose disease, prescribe treatment or override clinical judgment.

## What this repository does

1. **Screening benchmark.** Two models (HbA1c at least 6.5%, mean examination blood pressure at least 130/80 mmHg) are developed on NHANES 2015-2016 with separate training, calibration and validation partitions, then evaluated once, with frozen thresholds, on the entire 2017-2018 cycle. Predictors are age, recorded sex, BMI, waist circumference, smoking and vigorous recreation. No synthetic patient outcomes are used.
2. **Robustness analyses** (`src/extended.py`): survey-design (Rao-Wu) bootstrap, paired AUROC comparisons, rule-based and age-only baselines, a validation-sensitivity sweep, 30 repeated development splits, a reverse-direction cycle check, calibration slope and intercept, age-specific blood-pressure thresholds, net benefit, alternative endpoints.
3. **Post-quantum envelope** (`src/security.py`, `src/security_extended.py`): X25519 + ML-KEM-768 hybrid key establishment, HKDF-SHA256, AES-256-GCM, ML-DSA-44 signatures, bound to the model-manifest digest. 1,200 functional trials, 4,000 single-bit mutation trials (with and without re-signing) and a classical-versus-hybrid cost comparison.
4. **ISO control evidence matrix** (`docs/iso_control_matrix.csv`): a proposed engineering crosswalk, not a certification.

## Headline results (2017-2018 temporal test, n = 2,581)

| Task | Selected model | AUROC | Sensitivity | Specificity | PPV |
| --- | --- | --- | --- | --- | --- |
| HbA1c at least 6.5% | HGB full | 0.727 | 83.3% | 50.5% | 4.6% |
| Blood pressure at least 130/80 | LR core | 0.728 | 76.4% | 60.4% | 49.3% |

Read these with the caveats the analyses expose:

- Only 36 HbA1c-positive training participants, 12 in validation. Across 30 development splits AUROC was stable (SD 0.011) but HbA1c sensitivity ranged from 56% to 92% and model selection flipped between candidates.
- Blood-pressure sensitivity is 50.6% under age 50 and 95.0% at 50 or older with one threshold; age-specific thresholds chosen on validation data equalize it near 73% at a higher referral rate.
- An age-only model and fixed age or BMI rules are credible competitors; the learned models add about 0.026 (blood pressure) and 0.075 (HbA1c) AUROC over age alone.
- Calibration slopes are 0.85 to 0.88; mean predicted risk underestimates observed prevalence in the later cycle.
- Unweighted primary analysis; not national prevalence estimates.

All numbers are in `results/` (`study.json`, `extended.json`, `security.json`, `security_extended.json`, CSVs) and are regenerated by the scripts.

## Reproduce

Python 3.12 was used for the pinned environment (results were also reproduced to within 1e-6 on Python 3.14).

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
python src/study.py              # downloads 16 CDC XPT files, validates headers, runs the primary study
python src/security.py           # functional trials and timings
python src/extended.py           # robustness analyses
python src/security_extended.py  # mutation fuzz and classical-versus-hybrid cost
python -m unittest discover -s tests -v
```

`data/raw/`, `artifacts/` and generated figures are not committed; `study.py` fetches missing CDC files and `data/sources.json` records their SHA256 digests, which the tests verify. Predictive outputs reproduce with the pinned environment. Cryptographic timings use fresh randomness and host timing and will differ between runs.

## Layout

| Path | Purpose |
| --- | --- |
| `src/study.py` | Download, eligibility, endpoints, fitting, calibration, selection, evaluation |
| `src/extended.py` | Robustness analyses listed above |
| `src/security.py`, `src/security_extended.py` | Hybrid envelope, functional trials, mutation fuzz, cost comparison |
| `src/infer.py` | Research inference after checking a trusted manifest digest |
| `tests/` | 27 regression tests (cohort rules, digests, thresholds, envelope, extended-result consistency, fuzz) |
| `results/` | Numerical outputs, predictions, split manifest |
| `tools/build_site.py` | Generates the project page (`docs/index.html`) from `results/` |
| `docs/iso_control_matrix.csv` | Proposed ISO/IEC 27002 control evidence matrix |

## Research inference example

The example record contains invented feature values, not a patient.

```bash
python src/infer.py --record docs/example_features.json --trusted-manifest-sha256 TRUSTED_DIGEST
```

Obtain `TRUSTED_DIGEST` through an independently authenticated channel; hashing an untrusted download does not authenticate it. `joblib` can execute code when loading artifacts, so load only verified files.

## Scope stated plainly

- Screening endpoints are single-examination proxies, not confirmed diagnoses.
- The envelope is a single-process application harness: no TLS integration, PKI, key revocation, persistent replay state, forward secrecy, side-channel evaluation, penetration test or FIPS 140 validation.
- The ISO mapping is a proposed crosswalk. No certification is claimed.
- No clinical trial, IRB determination or deployment is claimed.
